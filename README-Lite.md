# MINI68 离线配置 · 轻量版 0.4.3

本文件说明完整 Windows 应用。EXE、完整 ZIP 和校验文件可从 [v0.4.3 发布页](https://github.com/q330483012/aula-mini68-offline/releases/tag/v0.4.3) 下载；构建和授权范围见 [仓库首页](README.md)。

Windows 10 / 11 64 位，供本机使用的非官方离线适配。使用与鼠标程序相同的 Tauri + Rust + 系统 WebView2 方案，键盘界面、设备定义、设置逻辑及音乐算法来自原狼蛛网页。

当前发布的单文件 EXE 为 **7,211,520 字节（6.88 MiB）**，包含内嵌界面、原生程序和 WebView2 加载器。ZIP 约 **4.87 MiB**，包含 EXE、说明和依赖许可证；相比原 Electron ZIP 的 153.2 MiB 缩小约 96.8%。系统共享的 WebView2 运行时不计入其中。

## 使用

1. 双击 `MINI68-Lite.exe`，无需安装 Node.js、Python 或音乐插件。单独复制这个 EXE 即可使用。
2. 系统需要已安装 Microsoft Edge WebView2 Runtime。本机已安装；准备好运行环境后，首次启动也能断网。未安装 WebView2 的其他电脑需要先安装运行时。体积不包含共享的 WebView2。
3. 用 USB 数据线连接 MINI68，关闭其他占用键盘的驱动页面，点击“连接键盘”。本机识别为 MINI68 HE MAX。
4. 设置完成后按原界面的“保存”。首次使用本版会创建独立配置，不自动导入浏览器或 Electron 版的配置文件。
5. 先设置并保存日常使用的普通灯效或自定义灯光，再进入 **灯效设定 → 音乐律动**，打开 **音乐自动切换** 开关。开关默认关闭，会记住你的选择；关闭后停止采集和音乐帧，恢复普通灯效。点窗口右上角 **×** 或 Ctrl+W 收到托盘后仍然有效。双击托盘可恢复；右键托盘选“退出”或 Ctrl+Q 才会完全退出。

界面主要文字最低 14 px，菜单与颜色输入框为 16 px，不再随窗口宽度缩得过小。键盘图中紧凑的按键标签使用单独字号。

**调色盘**在“自定义”“静态恒亮”等支持选色的灯效下显示；“百花争艳”等固件多彩效果不支持单独选色。自定义灯光先点击上方按键或勾选“全选”，再用色盘、明暗条、预设色、HEX 或 RGB 选色，最后点“保存”。HEX 输入修复为与色盘、RGB 一样更新选中按键。

无声时保持原有灯效；持续检测到声音约 150 毫秒后开始律动；连续静音约 1.5 秒后停止发送音乐帧，随后由固件的短暂超时恢复原有灯效。歌曲中的短暂停顿不会立即切回。声音设备暂不可用时也会停止音乐帧，并继续尝试采集。

自动切换使用固件已有的临时灯光接口，不反复保存普通灯效或逐键颜色，不刷写固件。声音判断由电脑后台程序完成；读取 Windows 默认播放设备的音量，不使用麦克风、不录音，也不区分音乐、视频、人声等持续声音，不包含独立频谱分析器。

音乐律动必须让程序留在后台。开关开启后，切换普通灯效、性能、宏、高级键或设置页都持续运行；音乐律动页只用于调整参数。关闭开关、完全退出或断开键盘后停止。重新打开程序并连接键盘后，会按记住的开关状态恢复，无需进入音乐律动页。休眠期间不运行，唤醒后需要有效的声音采样才会重新律动。原有灯效配置会保留。

## 本地增强

点击右上角 **本地增强**，可设置开机自启动及“组合键 → 单个按键”映射。这些设置独立于原界面的键盘硬件配置，保存在当前 Windows 用户目录。

开机自启动默认关闭。开启后，在当前用户登录 Windows 时自动收至托盘并恢复已启用的组合键映射；无需管理员权限。它不会自动连接键盘。手动打开窗口并连接键盘后，音乐自动切换按记住的开关状态恢复。关闭自启动开关即删除本程序自己的自启动项。

以 **Ctrl + J → Home** 为例：保留来源的 Ctrl 勾选，选择 J 和 Home，点击“添加规则”，勾选“启用组合键映射”，再点击“保存并应用”。可以展开“测试映射”，将光标放在第二行中间，按 Ctrl+J 应移动到当前行开头。未保存的修改会显示“待应用”。默认不预置或启用任何规则。

最多保存 32 条映射，支持 Ctrl、Alt、Shift、Win 与字母、数字、方向键等按键组合，目标为一个无修饰的按键。每次按下触发一次，不提供长按连发。重复来源及部分系统保留组合会被拒绝；被系统或其他程序占用的组合会显示未启用原因，可换组合后重新保存。

映射通过 Windows 全局热键实现，**作用于本机所有键盘**，不是 MINI68 独占映射，也不写入键盘。窗口可关闭到托盘，完全退出程序后停止。托盘右键菜单可暂停／恢复映射；管理员窗口需要同等权限，部分使用原始输入的游戏可能不支持。目标为普通 Home 时会临时释放并恢复按住的修饰键，避免输出成 Ctrl+Home。

## 功能范围

| 功能 | 轻量版 |
|---|---|
| 自定义按键、普通层和 Fn 层 | 保留原网页编辑和保存逻辑 |
| 宏录制、编辑、导入／导出、绑定 | 保留原逻辑 |
| 普通灯效、自定义灯光 | 保留原逻辑 |
| 音乐律动 | 独立开关、记住选择、原生音量采集、托盘运行；有声时律动，静音后恢复原灯效 |
| 性能 | 保留触发行程、RT、轴体选择等原逻辑 |
| 高级键 | 保留 RS、SOCD、DKS、MT、TGL |
| 设备设置 | 保留回报率、稳定性、校准等本型号原有选项 |
| 本地配置文件 | 保留创建、复制、导入／导出等原逻辑 |
| 组合键 → 单键映射 | 新增 Windows 全局热键、本地保存、冲突提示、托盘暂停 |
| 开机自启动 | 新增可选开关，默认关闭，登录后收到托盘 |
| 固件升级、账号／社区、云端素材 | 未提供；升级请使用官方工具 |

仅支持 MINI68 系列 USB 配置接口，本机验证型号为 MINI68 HE MAX。其他型号、接收器、蓝牙未验证。功能是否显示仍遵循原网页各型号的能力定义。

当前方案适合小体积、保留原界面及离线使用的目标。后续可以在现有通信基础上扩展逐键颜色、波浪、渐变和其他音乐算法；软件实时生成的动态效果需要程序在后台，能否保存到键盘后脱离电脑运行取决于固件能力，不支持把任意新算法直接写入固件。

## 验证范围

已验证真实键盘连接、配置读取，以及性能、高级键、宏页面显示。已验证 Windows 实际声音采集、窗口隐藏超过 10 秒后持续生成音乐灯效数据；页面无加载错误、无外网请求。

0.4.3 的自动切换检查涵盖默认关闭不采集、鼠标与键盘操作开关、播放时关闭停止采集及音乐帧、初始静音、播放声音、短暂停顿、声音设备暂不可用、托盘隐藏超过 10 秒后继续律动、持续静音停止音乐帧，以及切换普通灯效、性能、高级键、宏、设置页仍持续律动、跨页静音释放、关闭后返回设置不启动采集、重新加载并连接后不进入音乐页即可恢复、模拟断开后停止采集和音乐帧。

调色盘检查覆盖色盘实际点击、HEX、RGB 与预设色同步，及选中按键的自定义颜色数据；在 1000 和 1280 CSS 像素宽度下检查主要字号、调色盘可见性、音乐设置区滚动及横向溢出。写入均在测试中拦截。

JavaScript 测试 23 项、Rust 测试 4 项，涵盖开关、声音判定与切换时序、采集失败与恢复、过期异步响应、原生通信排序、排队灯效帧取消及合并，以及原有映射校验和目标按键临时释放／恢复修饰键的输入序列。

本地增强沿用 0.4.0 的实现与验证结果：已在独立测试配置中验证自启动开关往返、注册表启动命令、规则保存和重启恢复、隐藏启动，以及两个实例争用同一全局热键时的冲突提示。自启动测试使用独立注册表键，未更改用户实际自启动项。已通过真实 Windows 系统输入验证 Ctrl+J：前台及程序隐藏时，目标测试框均收到无 Ctrl 修饰的 Home，光标移动到当前行开头，未跳到整篇文字开头，也未插入 J。

验证使用独立测试配置，原生端强制只读。灯效写入在测试中被拦截并模拟应答，未修改当前按键、宏、校准或灯光设置。因此各功能写入后的实际效果、真实键盘音乐灯光的最终视觉效果尚未逐项验收，不能视为所有功能均已实测。

恢复原灯效的机制已依据官方 MINI68 HE MAX V1.73 型号镜像检查，见 `docs/music-switching.md`；尚未确认本机当前安装的固件与该镜像完全一致。

## 本地文件

EXE 首次运行把自身内嵌的程序和 `WebView2Loader.dll` 释放到 `%LOCALAPPDATA%\MINI68 Lite\runtime\<版本及内容标识>`，后续校验并复用。程序不会下载网页或运行时。

原界面配置、WebView2 用户数据位于 `%LOCALAPPDATA%\local.aula.mini68.offline\WebView2`；组合键配置为同级的 `desktop-settings.json`。自启动项为当前用户注册表 `Software\Microsoft\Windows\CurrentVersion\Run` 下的 `MINI68Lite`，指向已释放的程序。运行后产生的配置和缓存不计入 EXE 大小。本版与 Electron 版的用户数据隔离；请一次只运行一个版本。

## 重建

源码位于本项目的 `lite/`，与原 Electron 版本并存。已下载的网页资源先经 `scripts/prepare_web.py` 和 `scripts/prepare_lite.py` 生成。Rust 使用 GNU Windows x64 工具链，需 Cargo 依赖缓存或首次联网获取。

```powershell
.\scripts\build-lite.ps1
node --test tests/*.test.cjs
node scripts/local-check.cjs
node scripts/lite-check.cjs
node scripts/lighting-ui-check.cjs
.\scripts\package-lite.ps1
```

构建脚本使用 PATH 中的 Rust 和 MinGW-w64，保留已有的 Cargo/Rustup 环境变量；可通过 `CARGO_TARGET_DIR` 指定 ASCII 构建缓存路径，详见仓库首页。`Cargo.lock` 固定依赖版本；硬件测试需要连接 MINI68，会播放约 12 秒低音量测试音。

`scripts/local-check.cjs` 默认会将真实系统按键发送到自己的测试输入框，需要桌面已解锁。设置 `AULA_LITE_SKIP_INPUT=1` 可仅检查设置、自启动、冲突、持久化及隐藏启动；测试结果会明确记录跳过了系统输入检查。设置 `AULA_LITE_EXE` 可改测打包后的单文件程序。所有测试实例使用独立用户数据目录；键盘通信在测试模式下强制只读。
